JiuNuo Desktop Pet · Feibi Jiubi Exclusive Feature Test

How to use
1. Extract the complete portable package. For everyday use run "JiuNuoDesktopPet.exe" in the root folder; this launcher is only for demonstrating the exclusive actions.
2. If the desktop pet is already running, exit it from the tray first.
3. In the "test-tools" folder, double-click "FeibiJiubi-FeatureTest.exe".
4. The fixed order in Revision 6 is: kick the window, punch it flying, charge into it, stash it in the hat, tease her until the mischief bar is full, throw the hat and shatter the window into the hat, throw the hat and tear the window into the hat, and a hatless interruption followed by picking the hat back up. The step IDs in the report are Kick / Punch / Charge / HatStoreReturn / Tease / Shatter / Tear / HatlessInterruption. Window interactions only use the dedicated test window the program creates, and keep the real safety checks; teasing to fill the bar runs on its own and needs no window precheck.
5. Progress is shown only in the right-click menu, the test window title and the report; no speech bubbles appear. The hat stash, shatter, tear and hatless interruption steps show "Waiting for a right-click restore" after the performance; right-click and choose "Give the Windows Back", and the test only continues once the real window is confirmed restored. There is no timeout and no minimum wait; you can watch for a while to confirm the window is not restored automatically, then act. While an animation is running, do not cover or move the test window, so the window action is not interrupted.
6. If a step fails, the test stops at that step and does not run the following actions. Note the current step and hint, fix the problem (for example, something covering the window), then right-click and choose "Retry This Step"; the next step only starts once it passes.
7. To stop early, right-click and choose "Stop Exclusive Feature Test", click the pet once, or exit the pet. Afterwards the dedicated test window is closed and effects are cleaned up; everyday settings and save data never change.

Notes
- This launcher is for you to watch the actions and hear the sounds yourself; it shows the pet and the test window. It is not a background automated test or a screen recorder.
- The test state is isolated from everyday save data and deliberately turns off autonomous mischief; it does not trigger the version upgrade of your real settings, and you do not need to change everyday settings to trigger actions. In normal mode autonomous mischief is on by default; old v4-or-earlier configurations turn it on during the first upgrade, and turning it off yourself afterwards is kept.
- This launcher only demonstrates Feibi Jiubi's exclusive gameplay and no longer separately demonstrates walking, running, sleeping, window physics, size, mute or going home; mute, stopping and safety cleanup remain available.
- Normal mode also never restores a stashed, shattered or torn window on a timer; once the character finishes her performance she can move around normally. Only the right-click "Give the Windows Back" asks the pet to restore; clicking the hat or effects no longer triggers a return.
- In normal mode, while the hat already holds something she can still kick, punch or charge another window, and a right-click return first stops the current small action and then retrieves the original stashed window; she will not stash a second window or start a new hat special move. "Mischief status" explains the switch, charging, cooldown, waiting and occupancy. Test the autonomous rhythm and two real windows at once with the normal launcher; they are not part of these eight isolated demonstrations.
- If you right-click restore during the eighth performance, the simulated drag/toss stops immediately and returning the window takes priority. If the hatless sequence was not fully observed, the step is marked NeedsReview with Evidence.HatlessInterruptionObserved=false and does not count as a full pass for that step; you can run the launcher again to observe it fully.
- Quiet Mode, going home, resizing and dragging across screens keep the held result; switching characters, exiting, locking the screen, sleeping the PC, or a real change in display layout or work area still return it safely. Choosing stop during the test cleans up the program's own window and is not recorded as a normal restore pass.
- Speech bubble text is turned off for both Nuonuo and Feibi Jiubi; voices, the hunger bar or mischief bar, and the right-click/tray menus remain.
- Your existing size, volume and mute preferences are inherited; if you were muted, sound is not turned on automatically. You can mute from the right-click menu during the test.
- While testing, pay attention to how actions connect, window positions, the mischief bar and voices; if something goes wrong, note the approximate time and the action in progress so it can be matched against the trace log.
- After a special move finishes its destruction, the shards or two torn halves should go into the hat and the real window should stay minimized; it is only returned after your right-click restore. Shards should never be left scattered on the desktop permanently, and the window should never be restored automatically.
- Attacks should show a charge-up, a quick strike, a hit-stop/small impact sparkle, the window moving away quickly and a single rebound, with no extra crouching, reaching or gloating afterwards. The special move is slowed down so the charge-up and destruction are easy to see; she first calls out "Feiba Jiubi", and only after that approaches the window and throws her hat; when muted, the action simply continues.
- If a pet or test is already running, the launcher asks you to exit it first and does not hand the launch request to the old instance.
- Keep "test-tools" and "app" in the same portable folder; do not move this EXE on its own.
- For everyday use, double-click "JiuNuoDesktopPet.exe", the only normal launcher at the root of the portable folder; it never runs the test automatically. This test launcher stays in the subfolder.
- The step-by-step report is saved to %TEMP%\SoftMochiPet.FeatureTest\<session folder>\feature-test-report.json; FeatureDemoStarted/FeatureDemoFinished in the log record the corresponding folder.
- The report should be Revision 6. WaitingForManualRestore means normal waiting, not failure; ManualRestoreRequested means a real right-click request was accepted. ManualRestore.HeldSeconds records the actual wait, and RequestedAt records the request time; a quick restore is also valid, but does not mean long-term holding has been observed sufficiently.
- Completed requires the window action's actual displacement or minimize/return checks to pass; holding steps must go through a real right-click request and restore confirmation, including the hatless interruption step. It does not mean that this version's full real run, visuals and sound have passed manual acceptance. Multiple monitors/scaling, real mouse operation in normal mode, starting with Windows and screen locking still need manual checks; the demonstration never changes the Start with Windows setting.
